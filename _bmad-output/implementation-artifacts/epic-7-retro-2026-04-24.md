## Challenges

1. **Three dropped Epic 6 action items** — `atomicWriteConfig()`, post-patch rebuild doc, log retrieval issue. Root cause: retro commitments that floated in the retro doc but never became story tasks with explicit owners in a sprint plan. The 8-0 pattern fixes this permanently — dropped items become first-class tasks in the next epic's pre-work story.

2. **`meson setup builddir` bug in two stories** — Both 7-3 `ci.yml` and 7-3 `CONTRIBUTING.md` had the missing `ui` source dir argument. Pattern: Meson invocation details are non-obvious and appear in multiple places; each new file that references Meson is a new opportunity to get it wrong. No structural fix beyond the existing review process — already caught reliably.

3. **Planning artifact drift** — Architecture doc had wrong file paths; epic spec had stale tool references. Jeremy's position: the story review process is the right correction layer, not pre-story audits. Action: when a review corrects a planning artifact assumption, write the correction back to the source doc before marking the story done (added to SM review checklist).

4. **Release pipeline untested end-to-end** — The `release.yml` workflow is correctly wired and reviewed, but has never been exercised by a human pushing a real `v*` tag. No safe dry-run mechanism exists today (delete-tag-recreate is not sustainable). Addressed by Story 8-4.

5. **No canonical version source** — `v0.1.0` currently exists independently in AppStream metainfo, manifest comments, and potentially engine code with no cross-checking. A mismatched tag would produce a release with inconsistent version strings. Addressed by Story 8-4.
